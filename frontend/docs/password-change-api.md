# 본인 비밀번호 변경 API 제안

FR-03, BR-26, BR-51에 해당한다. 현재 `PATCH /api/v1/users/me`는 이름과 연락처만 받고, 별도의 비밀번호 변경 API가 없다. 이 문서는 프론트·백엔드 합의용 초안이다.

## 백엔드 계약

- 인증된 활성 회원·사서·관리자가 자신의 비밀번호를 변경한다. 요청에서 다른 사용자 ID를 받지 않는다.
- 제안 경로는 `POST /api/v1/auth/change-password`이고, 요청 필드는 `currentPassword`와 `newPassword`다. 성공 시 `204 No Content`를 반환한다.
- 저장된 해시로 현재 비밀번호를 검증하고 서버의 비밀번호 정책을 적용한다. 기존 공용 해시 함수는 Argon2로 신규 해시를 생성하며 bcrypt로 저장된 기존 해시도 검증한다. 신규 해시 정책은 공용 인증 구현과 일치시킨다.
- 인증 만료는 `401`, 비활성 계정은 `403`, 현재 비밀번호 불일치나 입력 정책 위반은 팀에서 합의한 코드와 필드 오류로 반환한다. 응답이나 로그에 입력 비밀번호 또는 해시를 포함하지 않는다.
- 변경 후 현재 세션과 다른 기기의 세션을 각각 유지할지 폐기할지 합의한다. 재로그인이 필요하면 쿠키 삭제와 서버의 세션 무효화 동작을 응답 계약에 포함한다.

## 프론트 연결

내 계정에 현재 비밀번호, 새 비밀번호, 새 비밀번호 확인을 추가한다. 확인 값은 브라우저에서만 비교하고 API로 전송하지 않는다. 처리 중 중복 제출을 막고 필드 오류와 세션 종료 시 재로그인 동선을 제공한다. API가 제공된 뒤 연결한다.
