# 01. 업무 분석 및 요구사항 정의

## 1. 시스템 개발 목적

본 프로젝트는 도서관의 회원, 도서, 소장본 및 대출·반납 업무를 통합 관리하는 웹 기반 시스템을 구축하는 것을 목표로 한다. 회원은 도서를 검색하고 자신의 이용 현황을 확인할 수 있으며, 사서는 실물 도서의 등록과 대출·반납 업무를 수행한다. 시스템 관리자는 계정과 사용자 권한을 관리한다.

본 시스템은 책의 제목·저자·출판사 등 **도서 서지정보**와 도서관이 실제로 보유한 **개별 소장본**을 구분한다. 동일한 책을 여러 권 보유하더라도 서지정보는 공통으로 관리하고, 대출과 상태 관리는 소장본 단위로 처리한다.

본 문서는 시스템에서 제공할 기능과 업무 규칙, 품질 요구사항을 정의한다. 각 업무의 세부 처리 순서와 예외 처리 절차는 단위 업무 기술서 및 업무 흐름도에서, 데이터 구조와 SQL 구현은 데이터 모델 관련 문서에서 구체화한다.

## 2. 업무 범위

### 2.1 포함 기능

1. **회원 및 계정 관리:** 일반 이용자의 회원가입과 로그인, 본인 정보 조회·수정 및 탈퇴를 지원한다. 모든 사용자는 본인의 이름·휴대전화번호·비밀번호를 직접 수정할 수 있다. 일반 회원의 별도 비활성화 기능은 운영하지 않는다. 관리자는 사서·관리자 업무용 계정을 생성·비활성화·재활성화하며, 생성된 계정의 역할은 변경하지 않는다.
2. **도서 및 소장본 관리:** 사서는 도서의 서지정보와 실제 소장본을 등록·수정한다. 소장본의 정상·파손·제적 상태를 관리하고 필요한 변경 이력을 보존한다.
3. **도서 검색 및 조회:** 회원과 관리자는 제적되지 않은 소장본이 1권 이상 존재하는 일반 열람 대상 도서만 검색·조회한다. 사서는 소장본이 0권이거나 모든 소장본이 제적된 도서를 포함한 전체 서지정보를 검색·조회한다. 도서의 서지정보, 분류, 대출 가능 여부를 조건으로 검색하고 상세정보 및 소장 현황을 조회한다.
4. **도서 대출 및 반납:** 회원은 사서를 통해 실물 도서를 대출·반납한다. 시스템은 대출 자격, 대출 권수 및 소장본 상태를 확인하고 처리 결과와 이용 이력을 기록한다.
5. **대출 연장과 연체 관리:** 회원은 허용된 범위에서 도서별 대출 기간을 연장할 수 있다. 시스템은 연체 여부를 판정해 연체 중 신규 대출·연장을 제한하고, 연체 도서를 반납한 뒤에는 해당 연체 일수만큼 신규 대출을 정지한다.
6. **기록 및 예외 관리:** 중요 정보 변경과 대출·반납·연장 이력을 보존한다. 잘못된 대출·반납의 정정을 지원하며 통신 오류로 인한 중복 처리를 방지한다.

각 기능의 사용 권한과 구체적인 조건은 3~5절에서 정의한다.

### 2.2 제외 기능

1. 외부 서지정보 API 연동 및 타 도서관과의 대출 연계
2. 대출 중인 도서의 예약, 온라인 대출 신청 및 별도 승인 대기 절차
3. 연체료·파손 배상금 산정과 결제, 벌점 부과 및 파손 책임자 확정
4. 문자·전화·이메일 자동 알림과 휴대전화번호 소유자 인증
5. 전자책 서비스, 도서 리뷰·평점·추천 및 외부 확장 메타데이터 관리
6. 여러 소장본의 일괄 등록 기능
7. 다중 서버 운영, 무중단 배포 및 모바일 전용 애플리케이션

## 3. 사용자 및 역할 정의

본 시스템의 사용자 역할은 **일반 회원**, **사서**, **시스템 관리자**로 구분한다. 관리자는 사서보다 모든 권한을 많이 갖는 상위 역할이 아니라, 직원 계정 관리라는 별도 업무를 담당한다. 모든 계정의 역할은 생성 시 정해지며 이후 변경하지 않는다. 모든 사용자는 본인의 이름·휴대전화번호·비밀번호를 직접 수정할 수 있으나, 다른 사용자의 개인정보를 수정할 수 없다.

### 3.1 일반 회원

- 직접 회원가입하고 로그인·로그아웃할 수 있다.
- 본인의 이름·휴대전화번호·비밀번호를 변경하고 자신의 계정 및 이용 현황을 조회할 수 있다.
- 도서를 검색하고 상세 서지정보와 대출 가능 여부를 확인할 수 있다.
- 사서에게 실물 도서의 대출·반납을 요청하고, 조건에 맞는 대출 건을 직접 연장할 수 있다.
- 현재 대출 및 과거 이용 기록을 조회하고, 미반납 도서가 없으면 반납 후 신규 대출 정지 기간 중에도 탈퇴할 수 있다. 일반 회원 계정에는 별도의 비활성화·재활성화 기능을 적용하지 않는다.

### 3.2 사서

- 도서 서지정보와 소장본을 등록·수정·관리하며 파손·수리·제적을 처리한다.
- 회원과 실물 소장본을 확인하여 대출·반납을 처리한다.
- 회원별·소장본별 이용 이력과 연체 현황을 조회하고, 업무상 필요한 회원 연락처를 확인할 수 있다.
- 잘못 처리한 대출·반납을 정해진 규칙에 따라 취소·정정하고 관련 이력을 확인한다.
- 다른 사용자의 개인정보를 수정하거나 직원 계정을 생성·비활성화·재활성화할 수 없다. 본인의 이름·휴대전화번호·비밀번호는 직접 수정할 수 있다.

### 3.3 관리자

- 사서·관리자 업무용 계정을 생성하며, 생성 시 `LIBRARIAN` 또는 `ADMIN` 역할을 지정한다. 기존 계정의 역할은 변경하지 않는다.
- 사서·관리자 업무용 계정을 비활성화·재활성화하고 필요한 계정 상태를 조회한다. 일반 회원의 가입·탈퇴 및 개인정보 수정은 대신 처리하지 않는다.
- 직원 계정의 생성 및 상태 변경 이력을 조회한다. 자신의 이름·휴대전화번호·비밀번호는 직접 수정할 수 있으나, 다른 사용자의 개인정보를 수정하지 않는다.
- 도서·소장본 관리와 대출·반납 등 사서의 실무는 수행할 수 없다.

사서와 관리자가 개인적으로 도서를 대출하려면 업무용 계정과 구분된 일반 회원 계정을 이용한다.

## 4. 기능 요구사항

기능 요구사항(FR)은 시스템에서 **무엇을 제공해야 하는지**를 정의한다. 기능을 실행할 수 있는 세부 조건과 제한은 5절의 업무 규칙(BR)에 따른다.

| ID | 기능명 | 기능 요구사항 |
| --- | --- | --- |
| FR-01 | 계정 등록 | 일반 이용자는 직접 `MEMBER` 계정으로 회원가입할 수 있다. 사서·관리자 업무용 계정은 관리자가 각각 `LIBRARIAN`, `ADMIN` 역할로 생성한다. |
| FR-02 | 사용자 정보 조회 | 모든 사용자는 본인 계정 정보를 조회할 수 있다. 사서는 도서관 업무상 필요한 회원 연락처를, 관리자는 직원 계정 관리에 필요한 상태·역할 정보를 조회할 수 있다. |
| FR-03 | 본인 정보 수정 | 일반 회원·사서·관리자는 본인의 이름·휴대전화번호·비밀번호를 직접 변경할 수 있다. 다른 사용자의 개인정보는 수정할 수 없다. |
| FR-04 | 회원 탈퇴·직원 계정 비활성화 | 일반 회원의 본인 탈퇴 기능과 관리자의 사서·관리자 업무용 계정 비활성화·재활성화 기능을 제공한다. 일반 회원 계정에는 별도의 비활성화 기능을 제공하지 않는다. 탈퇴에 따른 데이터 처리는 FR-23을 따른다. |
| FR-05 | 직원 계정 및 접근 권한 관리 | 관리자는 사서·관리자 계정을 생성할 때 역할을 지정하고, 직원 계정의 활성 상태와 관련 이력을 관리할 수 있다. 기존 계정의 역할을 변경하는 기능은 제공하지 않는다. |
| FR-06 | 도서 서지정보 등록 | 사서는 제목·저자·분류를 필수로 입력하여 도서 서지정보를 등록할 수 있다. 출판사·발행연도·ISBN은 선택 입력이며, ISBN이 없는 도서도 등록할 수 있다. |
| FR-07 | 도서 검색 | 회원·사서·관리자는 도서명·저자·ISBN·출판사·출판연도·분류·대출 가능 여부를 조건으로 검색할 수 있다. 회원·관리자는 제적되지 않은 소장본이 1권 이상 존재하는 일반 열람 대상 도서만 검색할 수 있다. 사서는 소장본이 0권이거나 모든 소장본이 제적된 도서를 포함한 전체 서지정보를 검색할 수 있다. 복수 조건 검색, 정렬 및 페이지 단위 조회를 지원한다. |
| FR-08 | 도서 상세 조회 | 회원·사서·관리자는 권한 범위에 속한 도서의 상세 서지정보, 전체 소장본 수 및 대출 가능한 소장본 수를 조회할 수 있다. 상세 조회에도 FR-07의 일반 열람 대상 기준을 동일하게 적용하며, 소장본이 0권인 도서는 사서만 상세 조회할 수 있다. |
| FR-09 | 도서 서지정보 수정 | 사서는 등록된 도서의 서지정보를 수정할 수 있으며, 중요 변경 이력을 보존한다. |
| FR-10 | 도서 서지정보 보존·소장본 제적 | 도서 서지정보는 삭제하지 않고 유지한다. 사서는 개별 소장본을 제적할 수 있다. |
| FR-11 | 소장본 관리 | 사서는 도서별 소장본을 등록하고 정상·파손·제적 상태를 관리할 수 있다. 소장본에는 고유 관리번호를 부여한다. |
| FR-12 | 도서 대출 처리 | 사서는 일반 회원의 미반납 권수, 현재 연체 여부, 반납 후 대출 정지 기간, 소장본 상태를 확인하고 대출 가능한 경우에만 기록을 생성한다. |
| FR-13 | 도서 반납 처리 | 사서는 실물 도서를 확인해 반납을 처리하고, 반납 일시·처리자·필요한 소장본 상태 변경을 기록한다. 연체 반납 시 신규 대출 정지 종료시각도 반영한다. |
| FR-14 | 도서 대출 연장 | 회원은 대출 중인 개별 도서에 대해 정해진 조건에서 기존 대출 건의 반납예정일을 연장할 수 있다. 새로운 대출 건은 생성하지 않고 연장 내역을 별도로 보존한다. |
| FR-15 | 연체 판정 및 조회 | 시스템은 현재·과거 연체 여부와 연체 일수를 판단하고, 회원과 사서에게 권한에 맞는 연체 현황 및 신규 대출 정지 종료시각을 제공한다. |
| FR-16 | 연체 회원 이용 제한 | 미반납 도서가 현재 연체 중이면 신규 대출과 모든 대출 연장을 금지한다. 연체 도서를 반납한 뒤 대출 정지 기간이 남아 있는 경우에는 신규 대출을 금지한다. |
| FR-17 | 로그인·로그아웃 | 등록된 사용자는 자신의 계정으로 로그인·로그아웃할 수 있다. |
| FR-18 | 회원 본인 대출 이력 조회 | 회원은 본인의 현재 대출과 과거 대출·반납·연장 이력을 조회할 수 있다. |
| FR-19 | 업무 대출 이력 조회 | 사서는 회원 또는 소장본을 기준으로 대출·반납·연장 및 연체 이력을 조회할 수 있다. |
| FR-20 | 중요 변경 이력 조회 | 시스템은 직원 계정 생성·상태 변경, 도서 서지정보 변경 및 소장본 상태 변경 이력을 기록한다. 관리자는 직원 계정 관련 변경 이력만 조회할 수 있으며, 사서는 도서 서지정보 및 소장본 상태 변경 이력만 조회할 수 있다. |
| FR-21 | 통신 오류 시 중복 처리 방지 | 대출·반납·연장·정정 요청이 재전송되더라도 동일한 업무가 중복 실행되지 않도록 한다. |
| FR-22 | 대출·반납 취소 및 정정 | 사서는 잘못된 대출·반납을 정해진 조건에 따라 취소·정정할 수 있으며 원본 기록과 정정 이력을 보존한다. |
| FR-23 | 회원 탈퇴 및 이용 이력 보존 | 회원 탈퇴 시 미반납 도서가 없는지 확인하고, 회원의 개인정보 및 로그인 정보를 제거한다. 대출 정지 기간이 남아 있어도 탈퇴를 허용하며 남은 정지 기간은 종료하고 새 가입 계정에 승계하지 않는다. 과거 도서별 대출·반납·연장 기록은 보존하되, 대출 기록뿐 아니라 연장·정정·중복 요청 처리 등 관련 기록에서 탈퇴 회원을 식별하거나 개인별 이용 내역을 재구성할 수 있는 연결을 해제한다. 도서·소장본 기준의 비식별 이용 이력과 사서의 업무 처리 기록은 필요한 범위에서 유지한다. 개인정보 제거 및 관련 데이터 변경은 하나의 데이터베이스 트랜잭션으로 처리하며, 일부 작업이 실패하면 전체 변경을 취소한다. |

## 5. 업무 규칙

업무 규칙(BR)은 각 기능이 **어떤 조건에서 허용·거부되는지**, 어떤 데이터를 유지해야 하는지를 정의한다. 구체적인 화면 메시지, 처리 순서 및 SQL은 단위 업무 기술서와 데이터 모델에서 다룬다.

| ID | 업무 규칙 | 상세 내용 |
| --- | --- | --- |
| BR-01 | 대출 대상 | 신규 대출은 활성 상태의 일반 회원 계정에 대해서만 허용한다. |
| BR-02 | 기본 대출 기간 | 대출 기간은 대출일로부터 14일이며, 날짜 판정은 한국 표준시를 기준으로 한다. |
| BR-03 | 최대 대출 권수 | 회원 한 명이 동시에 빌릴 수 있는 도서는 최대 5권이다. |
| BR-04 | 연체 회원 대출 제한 | 미반납 도서 중 한 권이라도 연체 중이거나, 반납 후 신규 대출 정지 기간이 아직 끝나지 않았다면 신규 대출을 허용하지 않는다. |
| BR-05 | 대출 가능한 소장본 | 정상 상태이고 다른 유효한 미반납 대출 건이 없는 소장본만 대출할 수 있다. 동일 소장본의 동시 중복 대출은 금지한다. |
| BR-06 | 반납 처리 기준 | 반납은 사서가 실물 도서를 확인한 뒤 완료하며, 실제 반납일시와 담당 사서를 기록한다. 연체 반납이면 BR-52에 따라 신규 대출 정지 종료시각을 반영한다. |
| BR-07 | 현재 연체 판정 | 반납하지 않은 도서의 반납예정일이 현재 날짜보다 이전인 경우 연체로 본다. 반납예정일 당일은 연체가 아니다. |
| BR-08 | 과거 연체 이력 | 반납 완료 건의 연체 일수는 한국 표준시 기준 실제 반납일과 연장 내역이 반영된 최종 반납예정일의 날짜 차이로 계산한다. 반납예정일 이내에 반납하면 0일로 본다. 연체 일수는 별도 중복 컬럼 없이 대출 기록에서 계산할 수 있다. |
| BR-09 | 이용 이력 보존 | 대출·반납·연장 기록은 반납 완료나 소장본 제적 후에도 보존한다. 오류 정정 시 원본을 임의로 삭제하지 않는다. |
| BR-10 | 역할별 권한 | 회원·사서·관리자는 허용된 업무만 수행한다. 관리자와 사서는 상대 역할의 전용 업무를 수행할 수 없다. 계정 역할은 생성 시 정해지며 이후 변경하지 않는다. 직무 변경이 필요한 직원은 기존 업무 계정을 비활성화하고 새 역할의 업무 계정을 별도로 생성한다. |
| BR-11 | 대출 연장 횟수 | 각 대출 건의 연장은 최대 1회만 허용한다. |
| BR-12 | 대출 연장 기간·기록 | 연장이 승인되면 기존 대출 건의 반납예정일을 7일 연장하고 연장 이력 1건을 별도로 생성한다. 새 대출 건은 생성하지 않는다. |
| BR-13 | 연장일 산정 | 연장 기간은 신청일이 아닌 기존 반납예정일을 기준으로 더한다. |
| BR-14 | 연체 시 연장 제한 | 회원의 미반납 도서 중 한 권이라도 연체되면 모든 대출 건의 연장을 제한한다. 도서 조회와 반납은 가능하다. |
| BR-15 | 대출 업무 방식 | 회원이 실물 도서를 사서에게 제시하고 사서가 대출을 처리한다. 온라인 대출 신청·승인 대기는 운영하지 않는다. |
| BR-16 | 회원 탈퇴 제한 | 미반납 도서가 없는 경우에만 일반 회원의 탈퇴를 허용한다. 과거 연체 이력이 있거나 반납 후 신규 대출 정지 기간이 아직 남아 있더라도 탈퇴를 막지 않는다. |
| BR-17 | 도서·소장본 구분 | 서지정보는 도서 단위로 관리하고, 대출은 별도의 식별자를 가진 개별 소장본 단위로 기록한다. |
| BR-18 | ISBN 중복 기준 | ISBN이 있으면 유효성을 확인하고 동일 ISBN으로 서지정보를 중복 등록하지 않는다. ISBN이 없으면 임의의 번호를 생성하지 않는다. |
| BR-19 | 소장본 관리번호 | 시스템은 소장본마다 중복되지 않는 관리번호를 자동으로 부여한다. 기존 관리번호는 제적 후에도 재사용하지 않는다. |
| BR-20 | 소장본 상태 | 소장본 운영 상태는 정상(ACTIVE), 파손(DAMAGED), 제적(RETIRED)으로 구분한다. 대출 중 여부는 미반납 대출 기록으로 판단한다. |
| BR-21 | 파손 도서 관리 | 파손된 도서는 반납 처리할 수 있으나 수리 또는 제적 전까지 신규 대출을 허용하지 않는다. 수리 후 정상 상태로 변경할 수 있다. |
| BR-22 | 파손 관련 제재 | 파손 상태와 발견 당시의 대출 기록은 관리하되, 회원에게 벌금·배상금·벌점 등을 부과하거나 책임자를 자동 확정하지 않는다. |
| BR-23 | 소장본 제적 | 대출 중인 소장본은 제적할 수 없다. 제적 시 사유를 기록하며 소장본 정보와 이용 이력은 유지한다. |
| BR-24 | 도서 검색·상세 조회의 노출 범위 | 회원과 관리자의 일반 검색·상세 조회에는 **제적되지 않은 소장본(`ACTIVE` 또는 `DAMAGED`)이 1권 이상 존재하는 도서**만 포함한다. 서지정보만 등록되어 소장본이 0권인 도서와 모든 소장본이 `RETIRED`인 도서는 제외한다. 사서는 두 경우를 포함한 전체 서지정보를 조회할 수 있다. `DAMAGED` 소장본만 있는 도서는 일반 검색에 표시하되 대출 가능한 소장본 수는 0권이다. |
| BR-25 | 연락처 입력·중복 | 활성 계정의 휴대전화번호는 필수이며 숫자 10~11자리로 저장한다. 동일한 번호를 둘 이상의 활성 일반 회원(`MEMBER`) 계정에 등록할 수 없다. 사서·관리자 업무용 계정과 일반 회원 계정 사이의 동일 번호 사용은 허용한다. 계정 생성 및 본인 연락처 수정 시 이 기준을 검사한다. |
| BR-26 | 개인정보 범위 | 일반 회원·사서·관리자는 본인의 이름·연락처·비밀번호를 수정할 수 있다. 다른 사용자의 개인정보는 수정할 수 없다. 사서는 도서관 업무상 필요한 회원 연락처만 조회하고, 관리자는 직원 계정 관리에 필요한 정보만 조회한다. 주소·생년월일·성별·이메일은 기본 수집 대상에서 제외한다. |
| BR-27 | 직원 계정 비활성화 | 관리자는 사서·관리자 업무용 계정만 비활성화·재활성화할 수 있다. 비활성 상태에서는 로그인할 수 없으며 해당 계정이 처리한 과거 업무 기록은 보존한다. 일반 회원 계정의 비활성화 기능은 제공하지 않는다. |
| BR-28 | 직원의 개인 대출 | 사서·관리자 업무용 계정으로는 도서를 대출할 수 없으며, 개인 대출은 별도 일반 회원 계정을 사용한다. |
| BR-29 | 마지막 관리자 보호 | 활성 관리자 계정은 최소 1개 유지해야 한다. 마지막 활성 관리자의 계정 비활성화는 허용하지 않는다. 관리자 역할은 변경하지 않으며, 업무용 계정의 삭제 기능은 제공하지 않는다. |
| BR-30 | 중요 변경 이력 | 직원 계정 생성 및 활성 상태 변경, 서지정보 변경, 소장본 상태 변경 시 대상, 처리자, 처리 시각과 필요한 변경 전후 내용을 기록한다. |
| BR-31 | 중요 변경 사유 | 직원 계정의 비활성화·재활성화와 소장본 파손·수리·제적 시에는 변경 사유를 반드시 기록한다. 단순한 서지정보 오탈자 수정에는 사유 입력을 강제하지 않는다. |
| BR-32 | 변경 이력 관리 | 중요 변경과 해당 이력은 함께 저장한다. 직원 계정 생성·상태 변경 이력은 관리자, 도서·소장본 변경 이력은 사서가 조회할 수 있다. |
| BR-33 | 개인정보 수정 이력 | 이름·연락처·비밀번호의 이전 값은 변경 이력으로 저장하지 않는다. |
| BR-34 | 도서 검색 조건 | 제목·저자·출판사는 부분 검색한다. ISBN 검색어는 ISBN-10 또는 ISBN-13의 유효성을 검사하고 **ISBN-13 저장 형식으로 정규화한 뒤 정확히 일치**하는 도서를 조회한다. 출판연도 범위, 도서 분류, 대출 가능 여부로 검색 범위를 좁힐 수 있으며 여러 조건은 모두 만족해야 한다. |
| BR-35 | 도서 검색 결과 | 검색 결과는 도서 단위로 표시하고 대출 가능한 소장본 수를 제공한다. 기본 정렬은 도서명순이며, 동일한 이름은 도서 ID순으로 정렬하고 한 페이지에 20건씩 표시한다. |
| BR-36 | 도서 분류 | 도서는 미리 정의한 분야별 분류로 검색할 수 있다. 실제 분류값과 도서의 분류 연결 방식은 데이터 모델에서 명시한다. |
| BR-37 | 중복 요청 처리 | 동일한 업무 요청이 재전송되더라도 중복으로 적용해서는 안 된다. 같은 요청으로 판별되는 경우에는 기존 처리 결과를 제공한다. |
| BR-38 | 동시 처리 제한 | 여러 요청이 동시에 실행되어도 회원당 대출 5권, 동일 소장본의 중복 대출 금지 및 활성 관리자 최소 1명 규칙을 위반해서는 안 된다. |
| BR-39 | ISBN 없는 도서 | ISBN이 없어도 도서를 등록할 수 있으며, 도서 자체는 별도의 고유 도서 ID로 식별한다. |
| BR-40 | ISBN 입력 검증 | ISBN이 입력되면 ISBN-10 또는 ISBN-13의 유효한 번호인지 확인한다. 형식이 잘못되거나 이미 등록된 ISBN은 거부한다. |
| BR-41 | ISBN 없는 도서의 중복 검토 | ISBN이 없는 도서를 등록할 때는 제목·저자·출판사 등으로 유사한 기존 도서를 확인하고, 사서가 기존 도서 활용 또는 신규 등록을 선택한다. 제목이 같다는 이유만으로 등록을 자동 차단하지 않는다. |
| BR-42 | 대출·반납 정정 권한 | 모든 활성 사서는 잘못된 대출·반납을 정정할 수 있다. 정정 사유와 처리자, 처리 시각을 남겨야 한다. |
| BR-43 | 잘못된 대출 정정 | 잘못 처리된 대출은 원본을 삭제하지 않고 취소 이력을 남긴다. 다만 **실물 도서가 여전히 반출 중이면 기록만 취소할 수 없고**, 도서관이 실물을 회수하여 현재 상태를 확인했거나 실제 반출이 없었던 입력 오류인 경우에만 취소할 수 있다. 취소 후 올바른 회원에게 대출해야 한다면 **별도 신규 대출(BP-01)의 모든 조건을 검사**한다. |
| BR-44 | 잘못된 반납 정정 | 실제로 반납되지 않았는데 반납 완료로 처리한 경우, 데이터 충돌이 없을 때만 미반납 상태로 복원할 수 있다. 원래의 잘못된 처리 기록은 보존한다. |
| BR-45 | 정정 충돌 제한 | 정정으로 회원당 대출 5권이나 소장본 중복 대출 제한을 위반하면 정정을 거부한다. 오반납 이후 해당 소장본에 다른 유효한 대출이 발생했다면, **대출자가 동일 회원인지와 후속 대출의 반납 완료 여부에 관계없이** 자동 미반납 복원을 거부한다. 다만 후속 대출이 잘못 처리된 것으로 확인되어 정당한 사유로 취소된 경우, 다른 충돌이 없는지 재검증한 후 최초 대출을 복원할 수 있다. |
| BR-46 | 탈퇴 시 개인정보 제거 | 일반 회원 탈퇴 시 로그인 권한을 종료하고 이름·연락처·로그인 인증정보 등 개인을 식별할 수 있는 정보를 제거한다. 탈퇴는 사서·관리자 업무용 계정의 비활성화와 구분한다. |
| BR-47 | 탈퇴 회원 이용 이력 | 과거 도서별 대출·반납·연장 기록은 보존하되 대출 기록과 탈퇴 회원의 식별 연결은 제거한다. 연장·정정 이력 및 중복 요청 처리 기록 등 연계 기록에도 탈퇴 회원의 신원을 알아낼 수 있거나 동일 탈퇴 회원의 기록을 개인별로 다시 묶을 수 있는 연결은 남기지 않는다. 탈퇴한 회원의 이용 이력은 소장본 기준으로만 조회할 수 있다. |
| BR-48 | 탈퇴 처리의 일관성 | 개인정보 제거 및 이용 이력 연결 해제는 하나의 트랜잭션으로 처리한다. 일부가 실패하면 전체 탈퇴 변경을 취소한다. |
| BR-49 | 탈퇴 후 계정 이용 | 탈퇴한 일반 회원 계정은 로그인하거나 과거 개인 대출 기록을 열람할 수 없다. 재가입은 새 일반 회원 계정으로 처리하며, 탈퇴 당시 남은 신규 대출 정지 기간은 종료하고 새 계정에 승계하지 않는다. |
| BR-50 | 직접 회원가입 | 일반 이용자는 관리자 승인 없이 회원가입하며, 가입 계정에는 일반 회원 권한만 부여된다. 로그인 ID는 **역할 및 활성·비활성 상태와 관계없이 로그인 식별자가 남아 있는 모든 계정에서 중복될 수 없다.** 휴대전화번호는 활성 일반 회원 계정끼리 중복될 수 없다(BR-25). 탈퇴로 로그인 식별자가 제거된 계정의 ID 재사용 여부는 별도 정책으로 정한다. |
| BR-51 | 본인정보 수정 제한 | 일반 회원·사서·관리자는 자신의 이름·휴대전화번호·비밀번호를 변경할 수 있다. 로그인 ID·사용자 식별자·역할·계정 상태는 직접 변경할 수 없으며, 다른 사용자의 개인정보도 수정할 수 없다. |
| BR-52 | 연체 반납 후 신규 대출 정지 | 연체 도서를 반납하면 연체한 달력 날짜 수만큼 신규 대출을 정지한다(상한 없음). 정지는 실제 반납 확정 시각부터 시작하여 **연체 일수 × 24시간** 뒤 종료한다. 여러 연체 건이 있으면 각 건의 정지 종료시각 중 **가장 늦은 시각**을 적용하며, 일수를 합산하지 않는다. 정지 기간에는 신규 대출만 제한하고, 기존 대출 연장은 BR-14 등 기존 연장 조건을 적용한다. 반납 기록이나 반납예정일이 정정되면 해당 회원의 정지 종료시각을 유효한 대출 이력으로 다시 계산한다. |

### 6.2 적용 범위 및 한계

- 본 시스템은 단일 서버에서 구동되는 학습용 웹 애플리케이션을 기준으로 한다.
- 대규모 동시 접속 부하 시험, 다중 서버 구성, 자동 확장 및 무중단 배포는 필수 범위에 포함하지 않는다.
- 모바일 전용 애플리케이션과 별도의 모바일 화면 최적화는 필수 범위에 포함하지 않는다.
- 휴대전화번호는 도서관 업무상 연락을 위해 수집하며, 자동 알림과 번호 소유자 인증은 제공하지 않는다. 업무용 계정과 별도 일반 회원 계정 사이의 동일 번호 사용은 허용한다.
- 파손 상태 및 발견 이력은 관리하지만 파손 책임자 판정, 파손 배상금·벌점 부과는 구현하지 않는다. 연체 반납 후 신규 대출 정지(BR-52)는 별도로 적용한다.
- 탈퇴 후 재가입하는 회원의 본인 여부를 확인하는 수단은 제공하지 않으므로, 남은 대출 정지 기간을 새 계정으로 승계하지 않으며 재가입을 통한 제한 우회 가능성은 시스템의 한계로 둔다.
- 기술적 세부 설계와 개별 테스트 시나리오는 후속 문서에 명시하며, 실제 구현 변경 사항은 관련 문서에 반영한다.
