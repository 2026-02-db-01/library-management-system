# 03-04. 용어 사전 목록

## 1. 작성 목적 및 적용 범위

본 문서는 도서관 관리 시스템에서 사용하는 **업무 용어, 데이터 명칭, 코드값과 계산 용어의 의미를 통일**하기 위한 표준 용어 사전이다. 개발자·문서 작성자·테스트 담당자가 같은 단어를 서로 다른 뜻으로 해석하지 않도록, 한국어 표준 용어를 정의하고 실제 데이터 모델의 속성과 연결한다.

기준 문서는 [[01. 업무 분석 및 요구사항 정의|01.-업무-분석-및-요구사항-정의]], BP-01–BP-11 단위 업무 기술서, [[03-01. 개념적 데이터 모델|03‐01.-개념적-데이터-모델]], [[03-02. 논리적 데이터 모델|03‐02.-논리적-데이터-모델]], [[03-03. 물리적 데이터 모델|03‐03.-물리적-데이터-모델]]이며, 물리적 명칭은 이번에 제공한 `database/schema.sql`의 **12개 테이블**을 기준으로 작성한다.

이 문서는 **용어의 뜻과 표준 명칭**을 정하는 문서다. 실제 컬럼 자료형·NULL·PK/FK·인덱스·DDL의 상세 정의는 03-03 및 후속 **테이블 기술서**, 값의 타입·길이·허용 범위는 후속 **도메인 정의서**에서 관리한다. 문서나 구현이 변경되면 용어 사전도 함께 개정한다.

## 2. 용어 사용 및 표기 원칙

| 항목 | 표준화 원칙 |
|---|---|
| **한글 명칭** | 표에서 지정한 표준 용어를 우선 사용한다. 한 화면·한 문서 안에서 같은 개념에 여러 이름을 붙이지 않는다. |
| **영문 명칭** | 엔터티·릴레이션은 `UPPER_SNAKE_CASE` 논리 표기, 실제 테이블·속성은 `lower_snake_case` 물리 표기를 따른다. |
| **역할과 상태** | `ACTIVE`는 계정 상태와 소장본 관리 상태 양쪽에 나타나지만 **서로 다른 코드 도메인**이다. 코드만으로 의미를 해석하지 않는다. |
| **도서와 소장본** | `BOOK`은 서지정보, `BOOK_COPY`는 실물 책 한 권이다. 대출 단위는 ISBN이나 BOOK이 아닌 BOOK_COPY다. |
| **날짜와 시각** | 반납예정일은 **날짜(`DATE`)**, 업무 확정 시각은 **시점(`TIMESTAMPTZ`)**이며 날짜 비교는 `Asia/Seoul`을 기준으로 한다. |
| **유도 정보** | 대출 중 여부·대출 가능 여부·연체 여부·연체 일수·연장 횟수·검색 노출 여부는 업무 기록으로 유도한다. 신규 대출 정지 종료시각은 재계산 가능한 **캐시**를 사용한다. |
| **원본·이력** | 정정으로 현재 유효 상태가 바뀌더라도 원래 처리 사실은 별도 이력에 보존한다. 탈퇴 회원의 개인정보 연결은 보존 대상이 아니다. |
| **미확정 사항** | 현재 합의되지 않은 값이나 운영 정책은 임의로 확정하지 않고 문서 말미의 **확인 필요 사항**에 적는다. |

## 3. 표준 업무 용어 사전

아래의 **용어 ID(T-001부터)**는 문서 관리용 식별자이며 데이터베이스에 저장하는 컬럼이 아니다. 「관련 데이터」의 `(유도)` 표시는 독립 컬럼이 아닌 조회·검증 시 계산되는 정보를 뜻한다.

## 4. 코드·상태·도메인 용어 사전

### 4.1 역할과 계정 상태

| 대상 물리 속성 | 코드값 | 업무 의미 | 허용·전이 규칙 |
|---|---|---|---|
| `app_user.role` | `MEMBER` | 일반 회원 | 본인이 가입할 때 지정, 변경 불가 |
| `app_user.role` | `LIBRARIAN` | 사서 | 관리자에 의해 생성, 변경 불가 |
| `app_user.role` | `ADMIN` | 관리자 | 기존 관리자가 생성(최초 관리자 예외), 변경 불가 |
| `app_user.account_status` | `ACTIVE` | 활성 계정 | 일반 회원 또는 직원에게 허용 |
| `app_user.account_status` | `INACTIVE` | 직원 비활성 계정 | LIBRARIAN·ADMIN에만 허용. 관리자만 전이 가능 |
| `app_user.account_status` | `WITHDRAWN` | 회원 탈퇴 완료 | MEMBER에만 허용. 개인정보 제거 및 복구 불가 |
| `staff_account_history.action_type` | `CREATE` | 직원 계정 생성 | 생성 이력; 새 직원 상태 ACTIVE |
| `staff_account_history.action_type` | `DEACTIVATE` | 직원 비활성화 | ACTIVE → INACTIVE, 사유 필수 |
| `staff_account_history.action_type` | `REACTIVATE` | 직원 재활성화 | INACTIVE → ACTIVE, 사유 필수 |

**구분:** 일반 회원에게 `INACTIVE` 상태를 부여하지 않으며, 직원 계정에는 `WITHDRAWN`을 적용하지 않는다. 마지막 활성 `ADMIN`은 비활성화할 수 없다. 역할 변경 이벤트는 존재하지 않는다.

### 4.2 소장본 관리 상태

| 속성 | 코드 | 의미 | 업무 규칙 |
|---|---|---|---|
| `book_copy.management_status` | `ACTIVE` | 정상 실물 | 유효한 미반납 대출이 없을 때만 대출 가능 |
| `book_copy.management_status` | `DAMAGED` | 파손 실물 | 신규 대출 불가; 수리 후 ACTIVE 가능 |
| `book_copy.management_status` | `RETIRED` | 제적 실물 | 신규 대출 불가; 상태 복원 불가; 이력 유지 |

**구분:** `LOANED`는 `management_status`에 존재하지 않는다. 이미 대출 중인지 여부는 **취소되지 않은 미반납 대출 기록**으로 판정한다. `BOOK`에는 `catalog_status`를 두지 않는다.

### 4.4 입력 도메인 및 기록 형식

| 도메인 | 관련 속성 | 기준 | 확정 상태 |
|---|---|---|---|
| 사용자 연락처 | `app_user.contact` | 하이픈을 제거한 숫자 10–11자리, 활성 MEMBER 사이에서만 고유 | 확정 |
| 로그인 ID | `app_user.login_id` | 값이 존재하는 계정 사이에서는 역할·활성 상태와 무관하게 고유 | 확정 |
| 도서 ISBN | `book.isbn` | 선택값. ISBN-10/13 검증 후 숫자 ISBN-13으로 통일; 있는 값은 고유 | 확정 |
| 도서 분류 | `book.category_code` | 영문 대문자로 시작하고 대문자·숫자·밑줄 사용. 실제 분야 코드 목록 필요 | **코드 목록 미확정** |
| 반납예정일 | `loan.initial_due_date / loan.current_due_date` | 달력상 날짜, Asia/Seoul 기준 계산 | 확정 |
| 업무 이벤트 시각 | `borrowed_at / returned_at / *_at` | 타임존 있는 실제 시점(TIMESTAMPTZ), 표시는 KST | 확정 |
| 요청 식별자 | `request_record.request_id` | 중복 재전송 판별을 위한 UUID | 확정 |
| 요청 지문 | `request_record.request_fingerprint` | 소문자 64자리 16진수(SHA-256 형식); 개인식별 데이터 원문 포함 금지 | 물리 형식 확정 |
| 이력 전후값 | `before_values / after_values` | 개인 식별값 없는 JSONB 객체형 감사 스냅샷 | 물리 형식 확정 |
| 요청 결과 | `request_record.result_code` | 처리 결과 코드 문자열; 코드값 표준 필요 | **코드 목록 미확정** |
| 요청 결과 보존기간 | `request_record` | 멱등성 재조회에 필요한 기간과 삭제 정책 | **정책 미확정** |

> `category_code`의 정규식 형태만 있다고 해서 실제 도서 분류 코드가 정해진 것은 아니다. 도메인 정의서에서 **허용값과 사용자 표시명**을 확정한 뒤 백엔드 검증과 DB 제약을 맞춰야 한다.

## 6. 계산·검증 용어 및 핵심 업무 규칙

| 표준 표현 | 업무상 계산 또는 검증 기준 | 근거 |
|---|---|---|
| **회원당 현재 대출 권수** | `is_cancelled = FALSE`이고 `returned_at IS NULL`인 LOAN을 회원별로 계산; 동시 최대 **5건** | BR-03 |
| **소장본의 유효한 미반납** | `copy_id`별 `is_cancelled = FALSE AND returned_at IS NULL`인 LOAN은 **동시 최대 1건** | BR-05 |
| **기본 반납예정일** | 대출 확정시각의 KST 날짜 + **14일** | BR-02 |
| **연장 후 반납예정일** | 신청일이 아니라 연장 전 만기일 + **7일**. LOAN당 **1회** | BR-11–BR-13 |
| **현재 연체 판단** | 유효한 미반납 LOAN의 `current_due_date`가 KST 오늘보다 이전이면 연체 | BR-07 |
| **반납 완료 건 연체 일수** | `max(0, KST 반납 날짜 − 최종 반납예정일)`(달력 날짜 차이) | BR-08 |
| **연체 반납 후 신규 대출 정지** | 반납 건별 `returned_at + (연체 일수 × 24시간)`; 여러 건은 종료시각 **최댓값**, 합산하지 않음 | BR-52 |
| **신규 대출 가능 조건** | ACTIVE MEMBER, 미반납 대출 5건 미만, 현재 연체 0건, 반납 후 정지 기간 종료, ACTIVE 소장본, 유효한 미반납 점유 0건 | BR-01·03–05 |
| **연장 가능 조건** | 본인 ACTIVE MEMBER의 유효 미반납 대출, 해당 대출 연장 0회, 모든 미반납 대출에 현재 연체 없음; **반납 후 정지만 남은 경우 연장 가능** | BR-11–BR-14·52 |
| **일반 검색 노출** | 해당 BOOK에 ACTIVE 또는 DAMAGED 소장본 **1권 이상** 있으면 회원·관리자 목록·상세에 표시. 0권 또는 모두 RETIRED는 사서만 조회 | BR-24 |
| **대출 가능 소장본 수** | 해당 BOOK의 ACTIVE 소장본 중 유효한 미반납 LOAN이 없는 수 | BR-05·FR-07 |
| **탈퇴 가능 조건** | 회원 본인 요청 + 유효한 미반납 대출 0건. 반납 후 신규 대출 정지가 남아 있어도 탈퇴 가능 | BR-16·FR-23 |
| **탈퇴 이력 보존** | LOAN과 업무 이력 자체는 보존하되 회원 식별 연결과 개인정보·로그 응답의 재식별 경로 제거 | BR-46–BR-49 |
| **잘못된 반납 복원 제한** | 오반납 이후 해당 소장본에 다른 유효 대출 발생 시 반납 여부·동일 회원 여부와 무관하게 자동 복원 거부 | BR-45 |
| **중복 요청** | 같은 request_id + 같은 요청 지문이면 기존 처리 결과, 다른 지문이면 충돌 거부 | BR-37 |
| **최소 활성 관리자** | ACTIVE ADMIN이 **1명 이상** 존재해야 하며 마지막 관리자 비활성화 금지 | BR-29·BR-38 |

## 7. 혼동하기 쉬운 용어 구분

| 구분할 용어 | 구별해야 하는 이유 |
|---|---|
| **도서(BOOK) vs 소장본(BOOK_COPY)** | BOOK은 공통 서지정보이고 소장본은 개별 실물이다. 도서명·ISBN 기준으로 대출하지 않는다. |
| **계정 상태 ACTIVE vs 소장본 상태 ACTIVE** | 같은 코드 문자열이지만 계정은 로그인 사용 가능, 소장본은 파손·제적되지 않은 상태를 뜻한다. |
| **정상 소장본 vs 대출 가능 소장본** | ACTIVE 실물도 이미 대출 중이면 대출 불가이다. |
| **현재 연체 vs 반납 후 신규 대출 정지** | 현재 연체는 신규 대출과 연장을 모두 제한한다. 반납 후 정지는 신규 대출만 제한한다. |
| **직원 비활성화 vs 회원 탈퇴** | 비활성화는 복구 가능·기록 보존, 탈퇴는 개인정보·대출 연결 제거·복구 불가. |
| **대출 취소 vs 반납 취소** | 대출 취소는 잘못된 대출의 효력을 제거하고, 반납 취소는 잘못된 반납 완료를 미반납으로 복원한다. |
| **반납 처리 사서 vs 대출 회원** | 사서 ID는 과거 업무 추적에 남고, 회원 ID는 탈퇴 시 대출 연결에서 제거한다. |
| **연장 이력 vs 새로운 대출** | 연장은 LOAN의 기한 변경 + LOAN_RENEWAL 1건이며 새 LOAN을 만들지 않는다. |
| **ISBN vs 도서 식별자** | ISBN은 없어도 되고 입력된 경우 유일하지만, 내부 PK인 book_id는 모든 BOOK에 필요하다. |
| **원본 업무 기록 vs 현재 유효 상태** | 원본 사실은 이력에 남아도 취소된 LOAN은 점유·연체·권수 계산에서 제외한다. |
| **이력 보존 vs 개인정보 보존** | 업무 기록 보존은 탈퇴자의 신원 및 여러 대출을 다시 연결할 수 있는 정보를 보존한다는 뜻이 아니다. |

## 8. 문서 관리 및 추가 확정 사항

### 8.1 추가 확정이 필요한 항목

| 항목 | 현재 상태 | 후속 조치 |
|---|---|---|
| **분류 코드 목록 및 표시명** | `category_code`의 저장 형식만 정의됨 | 도서 분류값 전체 목록·사용자 표시명 확정 후 도메인 정의서·API·DB 검증 동기화 |
| **신규 직원 최초 비밀번호 설정** | 관리자 직접 계정 생성은 확정, 직원 초기 인증 과정은 미확정 | BP-04·BP-09의 최초 비밀번호 설정·전달 방법 확정 |
| **회원 탈퇴 전 로그인 ID 재사용** | 탈퇴 시 login_id 제거, 동일 문자열 재사용 정책 미확정 | 기존 아이디 예약 여부 결정; 필요하면 추가 구조·개인정보 보존 영향 검토 |
| **중복 요청 기록 보존기간** | REQUEST_RECORD의 처리 구조는 정해짐, 보존기간은 미확정 | 운영·시험 요구를 반영한 기간과 정리 정책 결정 |
| **요청 결과 코드 목록** | result_code 속성 존재, 세부 코드값 미확정 | 업무별 성공·거절·오류 코드 표준 정의 |
| **정정 증빙 방식** | evidence_reference는 선택 참조 문자열 | 개인정보 없는 증빙 참조 형식 및 검증 절차 구체화 |

### 8.2 갱신 및 검증 기준

1. 용어·코드 변경 시 **01 요구사항 → 해당 BP 문서 → 03-01 → 03-02 → 03-03 / SQL → 이 용어 사전 → 테이블 기술서·테스트** 순으로 영향 범위를 확인한다.
2. 한국어 명칭만 바꾸는 경우에도 화면·API 응답·테스트 명칭에 다른 의미로 쓰인 곳이 없는지 점검한다.
3. 물리적 속성을 추가·삭제할 때는 5절 데이터 항목 대응 목록의 **12개 테이블·전체 컬럼**과 `schema.sql`의 목록을 다시 대조한다.
4. 이력 스냅샷과 요청 응답에는 회원 탈퇴 후 재식별 경로가 남지 않도록 허용 필드 목록을 점검한다.
5. 업무 용어가 코드값과 충돌할 경우 코드만 쓰지 말고 `계정 상태`, `소장본 관리 상태`, `요청 처리 상태`처럼 **적용 대상을 함께 표기**한다.
