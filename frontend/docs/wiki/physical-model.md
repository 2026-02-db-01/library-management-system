# 03-03. 물리적 데이터 모델

## 1. 작성 목적과 구현 기준

본 문서는 [[03-01. 개념적 데이터 모델|03‐01.-개념적-데이터-모델]]과 [[03-02. 논리적 데이터 모델|03‐02.-논리적-데이터-모델]]에서 정리한 **12개 릴레이션**을 PostgreSQL의 테이블·자료형·제약조건·인덱스로 구체화한다. 업무 규칙은 [[01. 업무 분석 및 요구사항 정의|01.-업무-분석-및-요구사항-정의]] 및 BP-01–BP-11의 최종 문서를 따른다.

**본 문서와 함께 제공하는 생성 DDL:** `database/schema.sql` (이 수정본에 포함된 파일). 기존 GitHub 저장소의 `database/schema.sql`은 **이번 작업에서 직접 변경하지 않았으므로**, 새 DDL과 일치한다고 가정해서는 안 된다. 저장소에 반영할 때에는 기존 파일과 비교하고 새 파일로 갱신해야 한다.

- **DBMS:** PostgreSQL. 실제 식별자는 소문자 `snake_case`를 사용한다. 대문자 릴레이션명은 논리적 표기이다.
- **범위:** 빈 데이터베이스에 적용할 최초 스키마 생성 DDL. 기존 DB의 자료를 보존하며 구조를 변경하는 마이그레이션 스크립트가 아니다. `DROP TABLE`을 포함하지 않는다.
- **테이블 수:** 핵심·관계 릴레이션 7개 + 변경·정정 이력 4개 + 요청 처리 기록 1개 = **총 12개**.
- **식별자:** `book_author`는 `(book_id, author_id)` 복합 PK, `request_record`는 요청자가 생성한 UUID PK, 나머지 10개 테이블은 `BIGINT GENERATED BY DEFAULT AS IDENTITY` PK를 적용한다.
- **시점과 날짜:** 대출·반납·연장·정정·이력 시점은 `TIMESTAMPTZ`로 저장한다. 반납예정일은 `DATE`이며, 연체 날짜 판정은 **Asia/Seoul**을 기준으로 한다. `TIMESTAMPTZ`는 절대 시점을 저장하므로 표시할 때 KST로 변환한다.
- **보장 범위:** SQL 제약으로 막는 문제와 서버 권한 검증·트랜잭션으로 막는 문제를 구분한다. 예를 들어 회원당 최대 **5권**, 마지막 활성 관리자 **1명 이상**은 단순 `UNIQUE`/`CHECK`로 보장하지 않는다.
- **검증 상태:** 제공 DDL은 본 문서에 맞춰 작성한 **실행용 초안**이다. 실제 PostgreSQL에 적용한 결과나 전체 통합 테스트가 완료되었다고 주장하지 않는다.

## 2. 물리 설계 의사결정

| 설계 항목 | 물리 설계 결정 | 근거·주의 사항 |
|---|---|---|
| 로그인 ID | `app_user.login_id`는 `NULL` 허용 `UNIQUE` | 값이 있는 모든 계정 사이에서 중복 금지. 회원 탈퇴 시 제거하여 `NULL` 처리. 과거 ID 재사용 허용 여부는 정책 미확정 |
| 연락처 | 숫자 10–11자리; 활성 `MEMBER`에 한한 **부분 UNIQUE 인덱스** | 직원–회원, 직원–직원의 번호 중복 허용 |
| 역할·상태 | 역할 `MEMBER/LIBRARIAN/ADMIN`, 직원 상태 `ACTIVE/INACTIVE`, 회원 상태 `ACTIVE/WITHDRAWN` | 계정 역할의 생성 후 변경은 DB 트리거로 차단. `WITHDRAWN`은 `INACTIVE`와 다른 종료 상태 |
| 회원 탈퇴 | `APP_USER`의 개인정보·해시·로그인 ID·정지 종료시각 제거, `LOAN.member_user_id`와 연계 요청 식별 연결 해제 | `LOAN`·연장·정정·소장본별 이력은 비식별 형태로 유지 |
| 도서 ISBN | `book.isbn VARCHAR(13) NULL UNIQUE` | ISBN 없는 도서 허용. 입력된 ISBN-10은 서비스에서 ISBN-13 변환·검증 |
| 도서 필수값 | 제목, 분류 코드, 저자 **1명 이상** | 저자 연결 1명 이상은 도서 등록 트랜잭션에서 검사 |
| 도서 상태 | `book.catalog_status` 없음 | 제적은 `book_copy`의 실물 상태이며 검색 노출은 소장본 상태에서 계산 |
| 소장본 상태 | `ACTIVE/DAMAGED/RETIRED`, 관리번호 `UNIQUE` | 대출 중 여부는 별도 상태로 저장하지 않음 |
| 대출 한도 | 회원별 유효 미반납 최대 **5건** | 회원 행 잠금·건수 재검증. 회원 ID 부분 UNIQUE **금지** |
| 소장본 중복 대출 | 유효 미반납 LOAN의 `copy_id` 부분 UNIQUE | 조건: `is_cancelled = FALSE AND returned_at IS NULL` |
| 취소·반납 정정 | `loan.is_cancelled`, `cancelled_at`, `returned_at`, 반납 담당자 + `loan_correction_history` | 현재 유효 상태와 정정 전의 처리 사실을 구분해 보존 |
| 대출 연장 | `loan_renewal.loan_id UNIQUE`; 전후 만기일 및 확정 시각 저장 | 대출당 성공한 연장 0..1건. 새 대출 생성하지 않음 |
| 연체 후 신규 대출 정지 | `app_user.borrowing_suspended_until TIMESTAMPTZ NULL` **캐시 사용** | 유효한 연체 반납 기록으로 계산 가능. 반납·정정 시 재계산, 탈퇴 시 NULL. 현재 미반납 연체와 구분 |
| 변경 이력 | 직원·도서·소장본·정정 이력 4개 테이블 | 현재 상태 변경과 원본 이력 저장을 같은 트랜잭션에서 실행 |
| 이력의 변경 전후 값 | `JSONB` 객체형 감사 스냅샷 | 변경 필드와 원본 처리 사실만 저장. **탈퇴 회원의 이름·전화번호·로그인 ID·user_id를 포함하지 않음** |
| 중복 요청 | `request_record(request_id UUID PK, request_fingerprint, 결과 등)` | 동일 ID·동일 내용 재전송이면 기존 결과. 동일 ID·다른 내용이면 충돌 처리 |
| 초기 관리자 | 초기 설정에서 최초 `ADMIN` 1개를 안전하게 생성 | 관리자 0명인 상태의 생성 예외. 평문 비밀번호 또는 해시 하드코딩 금지 |

**인증·운영 정책으로 남은 사항:** 신규 직원의 최초 비밀번호 설정 방식, 탈퇴 전 로그인 ID의 재사용 허용 여부, 요청 결과의 보존기간은 아직 결정되지 않았다. 이번 DDL은 현행 업무 데이터의 일관성을 위한 구조만 제공하며, 미확정 정책을 확정한 것으로 취급하지 않는다.

## 3. 테이블별 물리 스키마

**표기:** NN=`NOT NULL`, NULL=`NULL 허용`, PK=기본키, UK=`UNIQUE`, FK=외래키. 아래 표에서 **최초 생성 시 필수**와 **물리 컬럼의 NN 여부**가 다른 경우에는 회원 탈퇴 등 전체 생명주기를 반영한다.

### 3.1 `app_user` — 사용자 계정

| 컬럼 | 자료형·NULL | 제약 / 기본값 | 용도 |
|---|---|---|---|
| `user_id` | BIGINT / NN | PK, IDENTITY | 계정 내부 식별자 |
| `login_id` | VARCHAR(50) / NULL | UK, 일반 계정은 필수 | 로그인 ID; 탈퇴 시 제거 |
| `password_hash` | TEXT / NULL | 일반 계정은 필수 | 안전한 비밀번호 해시; 탈퇴 시 제거 |
| `full_name` | VARCHAR(100) / NULL | 일반 계정은 필수 | 본인 이름; 탈퇴 시 제거 |
| `contact` | VARCHAR(11) / NULL | 정규식 숫자 10–11자리, 활성 회원 부분 UK | 본인 연락처; 탈퇴 시 제거 |
| `role` | VARCHAR(16) / NN | MEMBER / LIBRARIAN / ADMIN | **생성 시 고정** 역할 |
| `account_status` | VARCHAR(16) / NN | 기본 ACTIVE | MEMBER: ACTIVE/WITHDRAWN, 직원: ACTIVE/INACTIVE |
| `borrowing_suspended_until` | TIMESTAMPTZ / NULL | 파생 캐시 | 회원의 반납 후 신규 대출 정지 종료시각 |
| `created_at` | TIMESTAMPTZ / NN | 기본 CURRENT_TIMESTAMP | 계정 생성 시각 |

- 활성 회원·직원 및 비활성 직원은 로그인 ID·해시·이름·연락처가 존재해야 한다. 탈퇴(`WITHDRAWN`)한 일반 회원은 이 네 값과 정지 종료시각이 **모두 NULL**이어야 한다.
- DB 트리거 `trg_app_user_role_immutable`은 생성된 계정의 `role` 변경을 금지하고, `trg_app_user_withdrawal_final`은 탈퇴 계정의 재활성화를 막는다. 마지막 관리자 보호, 직원 계정 생성 권한, 본인정보 수정 권한은 서버의 인증·트랜잭션에서 별도 검사한다.
- `login_id`의 `UNIQUE`는 NULL을 여러 건 허용하므로 탈퇴 계정들이 서로 충돌하지 않는다. **이는 과거 ID 재사용을 정책상 승인했다는 의미가 아니다.**
- `borrowing_suspended_until`은 조회 성능을 위한 **물리 설계 선택**이다. 실제 정지 종료시각은 항상 취소되지 않은 유효한 연체 반납을 기준으로 재계산한다.

### 3.2 `book` — 도서 서지정보

| 컬럼 | 자료형·NULL | 제약 / 기본값 | 용도 |
|---|---|---|---|
| `book_id` | BIGINT / NN | PK, IDENTITY | 도서 식별자 |
| `isbn` | VARCHAR(13) / NULL | UK, 숫자 13자리 CHECK(값 존재 시) | 선택 ISBN |
| `title` | VARCHAR(255) / NN | 공백만 입력 금지 | 도서명 |
| `publisher` | VARCHAR(150) / NULL | 공백만 입력 금지(값 존재 시) | 출판사 |
| `publication_year` | SMALLINT / NULL | 1–9999 CHECK(값 존재 시) | 발행연도 |
| `category_code` | VARCHAR(32) / NN | 코드 문자열 형식 CHECK | 필수 분류 |

`book`에는 **`catalog_status`를 만들지 않는다.** ISBN이 NULL인 서지정보도 생성할 수 있고, 소장본이 0권이어도 BOOK 행을 유지한다. 실제 허용 카테고리 목록은 용어·도메인 정의서와 서버 검증에서 동일하게 관리해야 한다. 이번 DDL의 형식 CHECK는 **실제 허용 코드 집합까지 확정하는 제약이 아니다.** ISBN 체크디지트 검증도 서비스에서 수행한다.

### 3.3 `author` — 저자

| 컬럼 | 자료형·NULL | 제약 / 기본값 | 용도 |
|---|---|---|---|
| `author_id` | BIGINT / NN | PK, IDENTITY | 저자 식별자 |
| `author_name` | VARCHAR(150) / NN | 공백만 입력 금지, 중복 허용 | 저자 이름 |

동명이인 때문에 `author_name`에는 UNIQUE를 두지 않는다.

### 3.4 `book_author` — 도서–저자 연결

| 컬럼 | 자료형·NULL | 제약 / 기본값 | 용도 |
|---|---|---|---|
| `book_id` | BIGINT / NN | 복합 PK, FK → `book` | 서지정보 |
| `author_id` | BIGINT / NN | 복합 PK, FK → `author` | 저자 |

`(book_id, author_id)`가 복합 PK다. 도서 하나의 **저자 최소 1명 연결**은 FK만으로 보장되지 않으므로 생성·수정 트랜잭션 종료 전 검사한다.

### 3.5 `book_copy` — 실물 소장본

| 컬럼 | 자료형·NULL | 제약 / 기본값 | 용도 |
|---|---|---|---|
| `copy_id` | BIGINT / NN | PK, IDENTITY | 개별 소장본 ID |
| `book_id` | BIGINT / NN | FK → `book` | 서지정보 참조 |
| `copy_code` | VARCHAR(50) / NN | UK, 공백만 입력 금지 | 시스템 발급 관리번호 |
| `management_status` | VARCHAR(16) / NN | 기본 ACTIVE, ACTIVE/DAMAGED/RETIRED | 실물 상태 |

`RETIRED`는 DB 트리거 `trg_book_copy_retired_final`로도 되돌릴 수 없게 한다. `LOANED`·`is_available` 컬럼은 두지 않는다. 공개 검색에는 `ACTIVE` 또는 `DAMAGED` 소장본이 1권 이상 있는 도서만 표시하고, 실제 대출 가능 여부는 **ACTIVE + 유효한 미반납 대출 없음**으로 판단한다.

### 3.6 `loan` — 대출·반납의 현재 유효 상태

| 컬럼 | 자료형·NULL | 제약 / 기본값 | 용도 |
|---|---|---|---|
| `loan_id` | BIGINT / NN | PK, IDENTITY | 대출 기록 ID |
| `member_user_id` | BIGINT / NULL | FK → `app_user` | 대출 시 MEMBER 필수, 탈퇴 후 NULL |
| `copy_id` | BIGINT / NN | FK → `book_copy` | 대출된 실물 소장본 |
| `checked_out_by_user_id` | BIGINT / NN | FK → `app_user` | 대출 처리 사서 |
| `borrowed_at` | TIMESTAMPTZ / NN | 기본 CURRENT_TIMESTAMP | 대출 확정 시점 |
| `initial_due_date` | DATE / NN | KST 대출 날짜 +14일 | 최초 반납예정일 |
| `current_due_date` | DATE / NN | 최초 만기일 이상 | 연장·허용 정정 반영 최종 만기일 |
| `returned_at` | TIMESTAMPTZ / NULL | 반납 처리 사서와 동시 NULL/동시 존재 | 유효한 실제 반납 시점 |
| `returned_by_user_id` | BIGINT / NULL | FK → `app_user`, 반납 쌍 CHECK | 반납 처리 사서 |
| `is_cancelled` | BOOLEAN / NN | 기본 FALSE | 원본 보존형 대출 취소 표시 |
| `cancelled_at` | TIMESTAMPTZ / NULL | 취소 시 필수, 취소 전 NULL | 취소 확정 시점 |

- **유효한 미반납:** `is_cancelled = FALSE AND returned_at IS NULL`. 취소된 대출은 대출 권수·소장본 점유·연체·정지 계산에서 제외한다.
- `returned_at` / `returned_by_user_id`는 항상 함께 NULL 또는 함께 값이 있어야 한다. 반납 취소 후 원래 반납 정보는 **`loan_correction_history`의 스냅샷**에서 추적한다.
- `member_user_id`는 과거 회원 탈퇴 처리를 위해 물리적으로 NULL을 허용한다. 신규 INSERT에서 회원 식별자 없이 대출을 생성하는 것은 `trg_loan_new_insert_guard`가 막고, **해당 계정이 실제 활성 MEMBER인지**는 서비스에서 검증한다.
- `current_due_date >= initial_due_date`, 반납 시각은 대출 시각보다 빠를 수 없음, `is_cancelled`와 `cancelled_at`의 짝 제약을 둔다.
- 대출 취소의 **실물 확인 조건**, 오반납 복원의 후속 재대출·회원 5권 조건, 날짜·시각 정정은 BP-11에 따른다.

### 3.7 `loan_renewal` — 성공한 연장 이력

| 컬럼 | 자료형·NULL | 제약 / 기본값 | 용도 |
|---|---|---|---|
| `renewal_id` | BIGINT / NN | PK, IDENTITY | 연장 사건 ID |
| `loan_id` | BIGINT / NN | **UK**, FK → `loan` | 대출당 최대 1회 |
| `renewed_at` | TIMESTAMPTZ / NN | 기본 CURRENT_TIMESTAMP | 연장 확정 시각 |
| `previous_due_date` | DATE / NN | 기존 만기일 | 변경 전 만기일 |
| `new_due_date` | DATE / NN | 기존 만기일 +7일 CHECK | 변경 후 만기일 |

연장 시 새 LOAN을 만들지 않는다. 기존 LOAN 만기일 수정과 이력 한 건 생성은 같은 트랜잭션으로 수행한다. 성공한 연장 사건은 이후 대출 취소가 발생해도 삭제하지 않는다.

### 3.8 `staff_account_history` — 직원 계정 생성·상태 변경 이력

| 컬럼 | 자료형·NULL | 제약 / 기본값 | 용도 |
|---|---|---|---|

**핵심 부분 UNIQUE 인덱스:**

~~~sql
CREATE UNIQUE INDEX uq_app_user_active_member_contact
  ON app_user (contact)
  WHERE role = 'MEMBER' AND account_status = 'ACTIVE';

CREATE UNIQUE INDEX uq_loan_valid_unreturned_copy
  ON loan (copy_id)
  WHERE is_cancelled = FALSE AND returned_at IS NULL;
~~~

> **금지할 잘못된 인덱스:** `UNIQUE(loan.member_user_id) WHERE returned_at IS NULL`. 이 인덱스는 회원당 최대 5권이 아니라 **1권만 허용**하게 되므로 사용하지 않는다. 또한 `is_cancelled = FALSE`가 빠진 소장본 점유 인덱스도 정정 취소 정책과 충돌한다.

### 5.1 회원당 동시 대출 최대 5권

1. 대출·오반납 복원·회원 탈퇴처럼 동일 회원의 대출 상태에 영향을 주는 요청은 **회원 행을 잠그는 일관된 순서**로 처리한다.
2. 유효 미반납(`is_cancelled = FALSE AND returned_at IS NULL`) 건수를 잠금 후 다시 조회한다. 신규 대출은 **현재 5건 이상이면 거부**하고, 반납 취소 복원은 복원 후 5건을 넘으면 거부한다.
3. 같은 소장본의 중복 점유는 소장본 행 잠금 및 `uq_loan_valid_unreturned_copy`로 이중 검증한다.
4. 임의로 회원별 부분 UNIQUE를 추가하지 않는다.

### 5.2 마지막 활성 관리자 최소 1명

관리자 비활성화는 활성 관리자 수를 최신 상태로 재확인한 뒤 처리한다. **모든 관리자 상태 변경이 공통 잠금/직렬화 규약**을 따라야 두 관리자가 서로를 동시에 비활성화하는 상황을 막을 수 있다. 단순히 매 요청 시작 시 `COUNT(*) > 1`을 검사하는 것만으로는 충분하지 않다.

### 5.3 연체 및 반납 후 신규 대출 정지

- **현재 연체:** 취소되지 않은 유효 미반납 대출의 `current_due_date`가 KST 오늘보다 과거인 경우. 이 상태에서는 새 대출과 **모든 연장** 불가.
- **과거 연체:** 취소되지 않고 실제 반납 완료된 건의 KST 날짜 차이. 음수는 0일.
- **건별 정지 종료:** `returned_at + (연체 일수 × INTERVAL '24 hours')`. 여러 건은 종료시각의 **최댓값**을 적용하며 합산하지 않음.
- **정지만 남은 회원:** 새 대출은 거부하지만, 현재 연체가 없는 기존 유효 대출은 다른 조건을 만족하면 연장 가능.
- 반납 취소·반납일시/만기일 정정·대출 취소 후에는 유효한 이력을 기준으로 `borrowing_suspended_until`을 다시 계산한다. 정정으로 정지 종료시각이 **단축·해제**되는 경우도 반영한다.

~~~sql
-- 날짜 계산 원칙을 보여주는 예시. :member_id는 응용 프로그램 바인드 값이다.
SELECT max(
         l.returned_at
         + GREATEST(
             (l.returned_at AT TIME ZONE 'Asia/Seoul')::date - l.current_due_date,
             0
           ) * INTERVAL '24 hours'
       ) AS borrowing_suspended_until
FROM loan AS l
WHERE l.member_user_id = :member_id
  AND l.is_cancelled = FALSE
  AND l.returned_at IS NOT NULL
  AND (l.returned_at AT TIME ZONE 'Asia/Seoul')::date > l.current_due_date;
~~~

이 쿼리는 **과거 연체 반납으로부터 계산되는 종료시각**을 보여준다. 신규 대출 허용 여부는 계산된 종료시각과 현재 시각을 비교하며, 별도로 현재 연체·대출 한도·소장본 상태도 검사한다. 회원 탈퇴 시에는 `LOAN.member_user_id` 연결을 해제하므로 회원별 재계산 대상에서 제외된다.

### 5.4 회원 탈퇴의 원자적 처리와 비식별화

1. 활성 MEMBER를 잠그고 유효 미반납 대출 **0건**인지 재검증한다.
2. 해당 회원의 `LOAN.member_user_id`를 NULL로 변경한다. 소장본 참조, 대출·반납·연장 시각 및 처리 직원 참조는 유지한다.
3. `request_record.actor_user_id`를 비롯하여 회원과 연결되는 요청 결과·정정 스냅샷에서 개인 식별정보가 남지 않도록 처리한다. **단순히 FK만 NULL로 만들면 충분하지 않을 수 있다.**
4. `app_user`의 `login_id`, `password_hash`, `full_name`, `contact`, `borrowing_suspended_until`을 NULL로 만들고 `account_status`를 `WITHDRAWN`으로 변경한다.
5. 위 DB 변경은 하나의 트랜잭션으로 확정한다. 기존 세션은 더 이상 유효하지 않게 처리한다. 외부 애플리케이션 로그·백업의 개인정보 정리는 DB 트랜잭션과 별도로 검증해야 한다.

**보존과 비식별화의 균형:** 직원의 대출·반납 처리 이력은 유지하지만, 과거 탈퇴 회원별로 대출 목록을 재구성할 수 있는 식별자·스냅샷·요청 원문은 남기지 않는다. `JSONB` 스냅샷이나 자유입력 사유에 개인정보를 기록하지 않도록 백엔드에서 저장 가능한 항목을 제한해야 한다.

### 5.5 중복 요청 처리

요청자가 생성한 UUID를 같은 업무 재전송에 재사용한다. 서버는 `request_id`가 이미 있는지 확인하고, **동일 지문**이면 완료된 결과를 그대로 반환한다. **다른 지문**이면 요청 ID 충돌로 거부한다. 동시에 같은 ID로 들어오는 요청 중 하나만 업무를 확정하도록 `request_record` 삽입·행 잠금과 실제 업무 변경을 하나의 트랜잭션 안에서 조정한다. `PENDING` 요청의 재시도·장애 복구 및 에러 결과 캐싱 범위는 API 구현에서 세부화한다.

## 6. 생성 순서·적용·검증

### 6.1 생성 순서와 파일

아래 순서로 외래키가 참조하는 테이블을 먼저 만든다.

`app_user` → `book` → `author` → `book_author` → `book_copy` → `loan` → `loan_renewal` → `staff_account_history` → `book_change_history` → `copy_status_history` → `loan_correction_history` → `request_record` → 일반 탐색 인덱스.

**실제 생성문은 함께 제공한 `database/schema.sql` 한 파일**로 관리한다. **기존 GitHub 저장소의 동명 파일에는 자동으로 반영되지 않는다.** 변경을 저장소에 적용하기 전 원래 SQL과 이번 SQL의 차이를 확인해야 한다.

빈 데이터베이스에서의 적용 예시:

~~~bash
psql -v ON_ERROR_STOP=1 -f database/schema.sql
~~~

데이터가 이미 있는 DB에는 무조건 실행하지 말고, 현행 데이터·제약조건을 확인한 뒤 별도의 마이그레이션을 준비한다. 최초 관리자 계정은 비밀번호 원문을 SQL 파일에 넣지 않고 별도의 안전한 초기 설정으로 생성한다.

### 6.2 스키마 검사용 SQL

~~~sql
-- public 스키마의 일반 테이블 목록: 본 모델 테이블 12개 기대
SELECT table_name
FROM information_schema.tables
WHERE table_schema = 'public' AND table_type = 'BASE TABLE'
ORDER BY table_name;

-- 주요 부분 UNIQUE 인덱스의 조건 확인
SELECT tablename, indexname, indexdef
FROM pg_indexes
WHERE schemaname = 'public'
  AND indexname IN ('uq_app_user_active_member_contact',
                    'uq_loan_valid_unreturned_copy')
ORDER BY tablename, indexname;

-- 탈퇴 가능한 회원 연결과 비밀번호 NULL 허용 확인
SELECT table_name, column_name, is_nullable
FROM information_schema.columns
WHERE table_schema = 'public'
  AND (table_name = 'loan' AND column_name = 'member_user_id'
       OR table_name = 'app_user' AND column_name IN ('login_id','password_hash','contact'))
ORDER BY table_name, column_name;
~~~

### 6.3 필수 검증 시나리오

| 검증 시나리오 | 기대 결과 / 담당 계층 |
|---|---|
| ISBN NULL인 서로 다른 도서 여러 건 등록 | 허용. 값이 있는 동일 ISBN 등록은 UK로 거부 |
| 저자가 0명인 도서 등록 확정 | 서비스·트랜잭션에서 거부 |
| 도서에 소장본 0권 또는 전부 RETIRED | 일반 검색 미노출, 사서 조회 가능 |
| DAMAGED 소장본만 존재 | 일반 검색 노출, 대출 가능 권수 0 |
| 일반 회원 동일 연락처 두 계정 | 두 번째 활성 회원은 부분 UK로 거부; 직원과 같은 번호는 허용 |
| 비활성 직원의 기존 로그인 ID 재사용 | UK로 거부 |
| 직원 계정의 ROLE UPDATE | DB 트리거 거부 |
| 마지막 활성 ADMIN 비활성화 시도 | 동시성 포함 서버 트랜잭션에서 거부 |
| 동일 회원의 유효 미반납 대출 **5건** | 허용; **6번째**는 서버에서 거부 |
| 동일 소장본의 유효 미반납 대출 2건 | 부분 UK로 거부 |
| 이미 취소된 미반납 대출의 소장본 재대출 | 다른 업무 조건 만족 시 가능 |
| 같은 대출에 연장 2건 | `loan_renewal.loan_id` UK로 거부 |
| 연장 시 기존 기한 +7일이 아닌 값 | CHECK로 거부 |
| 반납 시각만 있고 반납 사서가 없음 | 반납 쌍 CHECK로 거부 |
| 연체 3일 후 반납 | 반납 확정 시각부터 72시간 신규 대출 정지; 연장은 별도 조건 검사 |
| 오반납 복원 뒤 소장본에 후속 재대출 기록 존재 | 서버에서 복원 거부, 원본 기록 유지 |
| 정정으로 정지 종료시각이 달라짐 | 유효 이력 재계산·캐시 갱신 |
| 회원 탈퇴 전 미반납 도서 존재 | 서버에서 탈퇴 거부 |
| 미반납 0건 회원 탈퇴 | 개인정보 NULL, 과거 LOAN 회원 FK NULL, 소장본별 비식별 이력 유지 |
| 동일 UUID·동일 지문 재전송 | 중복 업무 없이 이전 결과 반환 |
| 동일 UUID·서로 다른 지문 전송 | 요청 충돌로 거부 |
| 상태 변경/정정 이력 INSERT 실패 | 트랜잭션 전체 롤백 |

위 항목은 **실행해야 할 테스트의 기준**이며, SQL 작성만으로 PostgreSQL 실행과 서비스 통합 검증이 끝난 것은 아니다.

## 7. 논리적 모델과의 일치 및 후속 작업

- **총 12개 테이블**이며 03-02의 APP_USER, BOOK, AUTHOR, BOOK_AUTHOR, BOOK_COPY, LOAN, LOAN_RENEWAL, STAFF_ACCOUNT_HISTORY, BOOK_CHANGE_HISTORY, COPY_STATUS_HISTORY, LOAN_CORRECTION_HISTORY, REQUEST_RECORD와 일치한다.
- 03-02의 **ISBN 선택·고유**, `BOOK`의 별도 제적 상태 없음, `BOOK_COPY`의 **ACTIVE/DAMAGED/RETIRED**, 회원당 **5권**, 대출당 연장 **1회**, 탈퇴 시 **회원 FK 해제**, 현재 상태와 감사 이력 분리, 요청 중복 방지 원칙을 반영한다.
- 물리적 단계에서 선택한 구현 세부사항은 **`JSONB` 감사 스냅샷**, **`UUID` 요청 ID**, **반납 후 정지 종료시각 캐시**, **역할 불변 트리거**, **현재 정책 기준의 `loan_renewal.loan_id UNIQUE`** 등이다.
- 논리 모델의 설명과 달리 12개 테이블을 넘어 새 테이블을 추가하지 않았다. 도서 분류 코드는 일단 BOOK의 속성으로 유지한다.
- **실제 DB 적용 전 확인:** 직원 초기 비밀번호 설정 방식, 탈퇴 전 로그인 ID 재사용 정책, 감사·요청 결과의 보관기간, `category_code`의 유효 코드 목록, 최초 관리자 초기화 절차, 외부 로그 비식별 처리, JSONB 스냅샷 허용 필드.
- 다음 문서인 **용어 사전·도메인 정의서**, **테이블 기술서**에서는 본 문서와 실제 `schema.sql`의 명칭·자료형·NULL·고유성·CHECK·FK·이력 정책을 그대로 대조한다.
