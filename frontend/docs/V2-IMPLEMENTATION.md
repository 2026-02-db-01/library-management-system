## 구현

- 기존 경로 유지, 사서 장서·저자 편집 경로와 소장본/정정/감사/이용 이력, 회원 본인정보/탈퇴, 직접 가입 데모 추가.
- 12테이블 도메인·시드·미리보기·메타데이터, 81컬럼·19 FK, 복합 PK, 연장 0..1 관계, 부분 UNIQUE, CHECK 의미와 인덱스 표시.
- 유효 미반납 = 취소 아님 + 반납 안 됨. 회원 5권, 소장본 1건, KST 14일, 기존 기한 +7일 연장 1회, 다른 현재 연체가 있으면 모든 연장 거부.
- 연체 반납 후 정지는 KST 연체 일수 ×24시간을 실제 반납 시각에 더한 최댓값. 정지만 남으면 기존 대출 연장 가능. 정정·취소 시 단축·해제까지 재계산.
- 파손·수리·제적, 시스템 자동 관리번호, 제적 복원 차단, 미반납 제적/수리 차단, 상태와 이력 원자적 변경.
- ISBN 선택·ISBN-10→13 정규화·체크디지트·고유성, 저자 ID 선택/동명이인, 저자 최소 1명, 무ISBN 유사 도서 검토, 분류·연도·대출 가능 AND 검색, 기본 제목/ID 정렬과 20건 페이지.
- 직원 역할 불변, 직원 상태 변경 사유/이력, 마지막 관리자 보호, 활성 계정 재검사, 본인정보만 수정.
- 대출 취소 실물 확인, 오반납 복원의 후속 유효 대출·회원 5권·소장본 점유·탈퇴 여부 검사. 원본과 정정 전후 이력을 보존하고 소장본 관리 상태를 자동 복구하지 않는다.
- UUID 요청 ID와 SHA-256 비식별 업무 지문, 동일 요청 재전송 결과 반환, 내용/처리자/대출 대상 충돌 차단. 성공 결과와 업무 변경을 함께 저장.
- 탈퇴 시 계정 개인정보·정지 제거, 대출 회원/요청자 연결 해제, 세션과 DB Flow 초기화. 탈퇴자의 과거 이용 이력을 개인별로 재구성하는 API/화면을 제공하지 않는다.
- 관리자 계정 화면은 회원 상태·직원 관리, 도서 통계는 비식별 집계. 사서 전용 서지/소장본/정정 감사 데이터는 관리자 DB 미리보기에서도 제한한다. 개인별 이용 이력 조회는 사서·본인 회원에게만 제공한다.
- DB Console은 읽기 전용 Mock 설계 뷰다. SQL 예시·전후 값·COMMIT/ROLLBACK 타임라인은 실제 SQL 실행 기록이 아니다. 모델/Store/표시 계층을 분리해 향후 API 어댑터 교체가 가능하도록 유지했다.

## 저장 데이터와 개인정보

기존 key `chaekdam-demo-state-v1`에서 persist version을 2로 올렸다. 구버전·미지원 버전·손상 JSON·불완전 배열은 합성 시드로 초기화한다. 저장소 사용 불가 시 메모리 데모로 동작한다. 구버전 데이터를 임의로 분류하거나 감사 이력을 만들어 마이그레이션하지 않는다.

실제 비밀번호·해시는 브라우저 데이터에 넣지 않는다. DB Console은 이름·로그인 ID·연락처·개인 대출 회원 연결·요청자·지문과 자유입력 사유/증빙을 숨긴다. 감사 스냅샷에는 업무 필드만 기록한다. 합성 개인정보도 실제 서비스의 보호 대상으로 취급한다. 역할 선택/가드는 데모 동작이며 서버 인증이나 보안 경계가 아니다.

## 미확정 정책과 안전한 제한

1. **분류 목록/표시명:** 실제 허용 목록 미확정. `DEMO_GENERAL`은 명시적 합성 데모 코드이며 운영 분류가 아니다. 다른 코드 등록은 제한한다.
2. **날짜·시각 정정:** BP-11 말미가 구체 운영안을 팀 확정 대상 제안으로 명시한다. 두 정정 유형은 타입·메타데이터·UI에 포함하되 실행은 설명과 함께 거부하고 원본을 유지한다. 대출 취소·오반납 복원은 동작한다.
3. **탈퇴 전 로그인 ID 재사용:** 개인정보 제거 후 과거 ID를 기억하는 예약표를 임의 생성하지 않는다. 탈퇴가 발생한 데모 상태에서는 신규 회원 가입을 보수적으로 제한한다. 초기화한 새 합성 시나리오에서는 가입 가능. 운영 재가입 정책을 확정한 것으로 해석하지 않는다.
4. **인증:** 실제 로그인·비밀번호 변경·해시 저장·직원 최초 인증·최초 관리자 초기화 절차는 백엔드 인증 설계 대상이다. 현재 역할 선택·계정 생성은 Mock임을 표시한다.
5. **요청 기록:** 결과 코드는 `MOCK_OK` 데모 표식이다. 실패 결과 캐시·PENDING 장애 복구·보관기간은 미확정이므로 성공 요청만 기록한다. 실패는 업무/이력/요청 성공 결과를 남기지 않고 롤백한다.
6. **DDL:** 최신 실제 SQL 파일을 확보하지 못했다. Wiki에 제시된 인덱스 이름은 그대로 사용하며 PK/FK/CHECK의 이름·표현은 모델 의미를 전달하는 SQL 예시다. 실행 DDL과 일치한다고 주장하지 않는다.

## 검증 실행

```sh
npm install
npm run typecheck
npm run lint
npm test
npm run build
npm run test:e2e
```

Playwright는 설치된 Chrome을 사용하며 포트 5174의 개발 서버를 자동 기동하거나 재사용한다. 테스트 코드는 Vitest `src/**/*.test.ts`와 Playwright `e2e/`로 분리했다. 결과·스크린샷은 `test-results/`에 생성되고 Git에서 제외한다.

자동 테스트는 5권/6권·중복 점유/반납·연체·연장 및 이력 실패 롤백·정지 산정·취소·후속 재대출·탈퇴/재가입 제한·제적 복원·마지막 관리자·연락처·ISBN·권한·메타데이터·개인정보·구버전 저장을 검증한다. 브라우저 테스트는 모든 주요 경로, 12테이블 상세, 검색·상세 모달·Escape, 역할 가드, 390px 레이아웃, 직원 생성/상태 전환, 본인정보, 서지 등록·소장본 추가·파손, 정정 롤백과 SQL 예시를 검증한다.

단일 브라우저 Store에서 연속 경합 요청을 모의 검증한다. PostgreSQL 행 잠금·실제 제약/트리거·다중 탭/다중 사용자 경쟁·네트워크 재시도·진짜 DB rollback·서버 권한·운영 로그/백업 개인정보 제거는 검증했다고 주장하지 않는다. 이들은 백엔드 통합 수용 테스트로 남긴다.
