# 책담 V2 DB Console 구현 노트

## 목적과 사용 범위

`index.html`은 한국 대학 도서관 책담 V2의 기존 역할 기반 React 앱에 적용할 디자인 참고 자료다. 파일을 브라우저에서 직접 열면 된다. 별도 설치, 빌드, 외부 폰트, 이미지, 네트워크 연결이 필요하지 않다. HTML, CSS, JavaScript가 한 파일에 있으며 이 문서가 디자인 토큰과 구현 기준을 설명한다.

실제 앱의 데이터베이스, 저장소, 라우터, 로그인 및 권한 코드는 변경하지 않았다. 12개 테이블과 컬럼은 요구사항을 설명하기 위해 작성한 **제안용 샘플 스키마**다. 실제 책담 스키마를 확인한 결과가 아니다. `사서 관리자`도 역할 표시 예시이며 현재 사용자를 인증했다는 의미가 아니다.

## 디자인 방향

흰 바탕, 중성 회색 작업 영역, 짙은 네이비 선택 상태로 구성한다. Linear에서 참고한 원칙은 안정된 탐색 위치, 정렬된 정보 밀도, 작은 반경, 얇은 구분선, 명확한 선택 상태, 맥락 가까이에 있는 세부 정보다. 로고나 제품 화면을 복제하지 않는다.

장식용 그라디언트, 글래스 효과, 네온, 제목 위 작은 장식 문구, 불필요한 큰 숫자나 통계는 사용하지 않는다. 제목은 바로 `데이터베이스`로 시작한다. 반복되는 사각형은 장식 카드가 아니라 실제 ERD 엔터티다. 본문은 16px를 기준으로 하고 DB 식별자·메타데이터는 정보 밀도를 위해 10–14px를 사용했다. 이는 일반 본문 16px 기준의 의도적인 예외이며 기존 앱에서 확대 설정과 함께 확인해야 한다.

폰트는 설치된 Pretendard → Noto Sans KR → Apple SD Gothic Neo → 맑은 고딕 순으로 사용한다. 식별자와 SQL은 시스템 고정폭 글꼴이다. 외부 폰트를 내려받지 않는다. 선택한 색상, 폰트, 간격은 이 참고 화면에서 정한 값이며 확정된 책담 브랜드 가이드는 아니다.

## 레이아웃과 반응형 동작

상위 구조는 `AppShell → Sidebar + Main`이다. Main은 상단 경로, 페이지 제목, 섹션 이동 링크, ERD 및 상세 패널, 트랜잭션 영역, 푸터 순서다. 제목 위 장식용 라벨은 없다. 두 탐색 메뉴는 동일한 스키마와 트랜잭션 섹션으로 이동하며 별개의 중복 페이지를 만들지 않는다.

| 뷰포트 | 탐색 | ERD | 컬럼 상세 |
| --- | --- | --- | --- |
| 1600px 이상 | 왼쪽 224px | 4열, 노드 간격 48×32px | 오른쪽 320px |
| 1280–1599px | 왼쪽 196px | 4열, 노드 간격 48×24px | 오른쪽 288px |
| 1024–1279px | 왼쪽 176px | 3열, 노드 간격 32×20px | 오른쪽 264px |
| 768–1023px | 왼쪽 164px | 3열 | ERD 아래, 컬럼 목록 2열 |
| 400–767px | 상단 메뉴 | 2열 | 아래에 쌓기, 컬럼 목록 2열 |
| 375–399px | 상단 메뉴 | 1열 | 아래에 쌓기, 컬럼 목록 1열 |

모바일에서는 중복 테이블 목록만 감추고 12개 ERD 노드와 전체 컬럼 정보는 유지한다. 테이블 검색은 데스크톱 보조 기능이다. 모바일에서도 모든 테이블을 직접 선택할 수 있다. 페이지 전체에 가로 스크롤을 만들지 않고 세로로 재배치한다. 긴 기술 식별자는 줄바꿈한다. 사이드바의 축약된 식별자는 접근 가능한 전체 이름 및 해당 테이블 상세로 확인한다.

페이지 콘텐츠와 ERD 노드는 CSS Grid의 정상 흐름에 둔다. SVG 관계선만 캔버스에 고정하는 비대화형 오버레이다. ResizeObserver로 실제 노드 위치를 읽어 선을 다시 그린다. 선택 테이블 관련 선은 네이비로 강조한다. 카드가 선 위에 놓이므로 떨어진 노드를 잇는 선 일부는 중간 카드 아래로 지나갈 수 있다. 연결 대상과 방향의 정확한 정보는 상세 패널의 텍스트 목록이 제공한다. 이것은 자유 배치·드래그·직교 경로 탐색을 지원하는 상용 ERD 엔진이 아니다.

모든 컬럼을 카드에 펼치지 않는다. 캔버스에는 첫 3개 컬럼, 총 컬럼 수와 추가 개수를 표시하고 선택한 테이블은 전체 컬럼을 상세 패널에 표시한다. 이것으로 식별·비교·탐색을 빠르게 하고 컬럼 상세의 가독성을 유지한다.

## 샘플 스키마: 정확히 12개 테이블

| 테이블 | 용도 | 컬럼 수 | FK 대상 |
| --- | --- | --- | --- |
| `departments` | 학과 | 4 | 없음 |
| `users` | 이용자 | 6 | `roles`, `departments` |
| `roles` | 역할 | 3 | 없음 |
| `authors` | 저자 | 4 | 없음 |
| `categories` | 분류 | 3 | 없음 |
| `books` | 도서 서지 | 6 | 없음 |
| `book_authors` | 도서–저자 연결 | 3 | `books`, `authors` |
| `reservations` | 예약 | 6 | `books`, `users` |
| `book_categories` | 도서–분류 연결 | 3 | `books`, `categories` |
| `copies` | 개별 소장 자료 | 5 | `books` |
| `loans` | 대출 | 8 | `copies`, `users` |
| `fines` | 연체료 | 5 | `loans` |

총 12개 FK 관계다. FK는 N측에 있으며 연결된 부모는 1측이다. `users.department_id`는 NULL 허용이므로 각 이용자의 학과는 0 또는 1개이고, 각 학과에는 이용자가 0명 이상일 수 있다. 다른 FK는 NOT NULL이다. `book_authors`와 `book_categories`는 두 FK를 합쳐 복합 PK로 사용하는 제안이다. 캔버스에서는 PK를 우선 표시하고 상세 패널에서는 `PK/FK`를 모두 표시한다. 모든 외래키 이름, 타입, NULL 허용 여부는 HTML의 `tables`와 `relations` 데이터에 들어 있다.

실제 스키마 적용 전에는 API 또는 확정된 DDL에서 컬럼·제약 조건·관계 메타데이터를 받아야 한다. 삭제 전파, 인덱스, ENUM, 타임존, 연체료 계산, 대출 중복 제한은 이 디자인 참고 자료가 확정하지 않는다. 화면에 표시한 UNIQUE 및 금액 조건도 제안 설명이며 실행 가능한 DDL을 생성하지 않는다.

## 구현된 상호작용

1. 테이블 목록 또는 ERD 노드를 선택하면 선택 표시, 전체 컬럼, NULL 조건, PK/FK, 관계 목록이 함께 바뀐다. 기본 선택은 `loans`다.
2. 테이블 이름 검색은 영문 식별자와 한국어 이름을 같은 규칙으로 검색한다. 왼쪽 목록을 필터링하고 캔버스에서 비일치 항목을 흐리게 표시한다. 입력을 비우면 복원된다. 결과가 없으면 안내 문구를 표시한다.
3. 관계선 체크박스는 선만 숨기거나 표시한다. 관계 텍스트는 항상 상세 패널에서 확인할 수 있다.
4. 스키마·트랜잭션 링크는 각 섹션으로 스크롤하고 포커스를 이동한다. URL 변경이나 React 라우터에 의존하지 않는다.
5. `구현 노트` 링크는 이 문서를 다운로드한다. 호스트 미리보기가 다운로드를 제한하면 프로젝트 파일 목록에서 `design-notes.md`를 연다.

## Mock 트랜잭션 상태 모델

화면과 각 로그 항목에 Mock을 명시한다. 쿼리는 읽기 전용 **의사 SQL 미리보기**이며 임의 SQL 편집기나 실제 DB 실행기가 아니다. UUID 컬럼을 설명하면서 `LN-2026-001`, `COPY-MOCK`처럼 사람이 읽기 쉬운 표시용 ID를 사용하므로 이 SQL은 실제 PostgreSQL에서 실행할 수 없다. INSERT는 필수 일시와 유효한 FK 등도 생략한 디자인 예시다.

`committed`는 확정된 대출 목록, `draft`는 임시 복사본, `pending`은 미확정 변경 명령 수다. 저장은 현재 브라우저 탭의 메모리만 사용하고 새로고침하면 초기화된다. localStorage나 서버를 사용하지 않는다.

| 명령 | 동작 | 피드백 |
| --- | --- | --- |
| Mock SELECT | 임시 변경이 있으면 draft, 없으면 committed를 조회 | 기준 대출 상태, 전체 건수, 미확정 포함 여부 |
| Mock INSERT | draft에 새 샘플 대출 추가 | 표시 ID, 미확정 표시, 증가한 건수 |
| Mock UPDATE | 기준 대출을 `대출 중 → 반납 완료`로 변경 | 변경 전후 상태, COMMIT/ROLLBACK 안내 |
| Mock COMMIT | draft를 committed에 반영하고 임시 상태 해제 | 확정 명령 수, 현재 건수 |
| Mock ROLLBACK | draft를 버리고 확정 상태 유지 | 취소 명령 수, 복원된 상태 |

COMMIT과 ROLLBACK은 미확정 변경이 있을 때만 활성화한다. UPDATE를 같은 상태에 다시 적용하면 변경 0건을 기록한다. 초기화는 대출 1건·대출 중으로 되돌리고 기록도 초기화한다. 초기화 대상은 명시된 Mock 데이터뿐이다. 각 명령은 SQL 미리보기, 실행 로그, 피드백을 갱신한다. COMMIT/ROLLBACK 후에는 SELECT 버튼으로 포커스를 돌려 비활성화된 버튼에 포커스가 남지 않게 한다.

최초 실행 기록 6건은 SELECT, INSERT, UPDATE, COMMIT, ROLLBACK을 한눈에 보여 주는 **정적 예시**이며 모든 설명에 `예시`를 붙였다. 이 기록은 현재 시뮬레이터 데이터와 독립적이다. 이후 실제 클릭 기록은 현재 브라우저 시간을 사용하며 최대 20건을 최신순으로 유지한다. 브라우저 시간은 서버 감사 시각이 아니다. 실제 앱에서는 서버가 발급한 transaction ID, actor ID, 결과, 타임스탬프를 사용해야 한다.

## 기존 React 앱 적용

새 앱으로 갈아엎지 말고 기존 셸과 역할 기반 메뉴를 유지한다. 페이지 내부만 다음 책임으로 나누는 것을 권장한다.

| 컴포넌트 | 책임 | 주요 입력 / 콜백 |
| --- | --- | --- |
| `DbConsolePage` | 선택·검색·트랜잭션 상태 조합 | schema, currentUser, capabilities |
| `SchemaToolbar` | 스키마 이름, 관계선 표시 | schemaName, showRelations, onToggle |
| `TableNavigator` | 검색과 테이블 선택 | tables, query, selectedId, onSelect |
| `ErdCanvas` | 반응형 노드와 관계선 | tables, relations, selectedId, onSelect |
| `TableInspector` | 전체 컬럼·제약·관계 | selectedTable, relatedEdges |
| `MockTransactionPanel` | draft/committed 시뮬레이션 | mockState, dispatch |
| `TransactionTimeline` | 명령 기록과 결과 | events |

선택 상태는 상위 페이지의 한 상태값에서 파생한다. 양쪽 목록과 상세가 독립 상태를 갖지 않게 한다. 트랜잭션은 `useReducer` 또는 기존 상태 도구의 단일 모델에서 처리하며 COMMIT 성공 이후에도 확정 데이터가 목록·건수·피드백에 일관되게 반영되도록 한다. ResizeObserver는 effect에서 등록하고 cleanup에서 해제한다. SVG 생성은 React SVG 엘리먼트로 옮기고 `window` 접근은 마운트 이후에 수행한다. 이 참고 자료의 DOM 기반 이벤트 코드를 React 컴포넌트에 그대로 섞지 않는다.

기존 앱의 권한 확인 함수와 서버 정책을 사용한다. 역할명만 보고 수정 권한을 추론하지 않는다. 스키마 열람, 트랜잭션 열람, 실데이터 수정은 제품 정책에 맞게 별도 capability로 연결할 수 있으나 이 문서는 실제 권한명이나 역할 매핑을 새로 정의하지 않는다. 버튼을 숨기는 것은 서버 권한 검증을 대체하지 않는다. 현재 HTML의 Mock 명령은 학습용으로 모두 노출한다.

실제 API로 확장할 때는 요청 중 상태, 서버 오류, 권한 없음, 빈 스키마, 동시 수정 충돌, 감사 기록을 별도로 설계한다. 현재 버전은 동기식 메모리 시뮬레이터이므로 가짜 로딩이나 가짜 서버 성공 응답을 추가하지 않았다.

## 접근성 기준

- `lang="ko"`, 본문 이동 링크, main/nav/aside/section 랜드마크와 순서 있는 제목을 제공한다.
- 실제 버튼·링크·체크박스를 사용한다. 노드는 Tab으로 도달하고 Enter/Space로 선택한다. 검색에는 지속적인 접근 가능한 이름이 있다.
- 선택 상태는 네이비 색뿐 아니라 테두리, 바탕, `aria-pressed`로 전달한다. PK/FK 및 트랜잭션 결과도 텍스트로 구분한다.
- 포커스 링은 3px, 간격 3px로 표시한다. 같은 노드를 선택해도 DOM 버튼을 재생성하지 않아 포커스를 유지한다.
- 테이블 선택 안내와 SQL 결과는 별도의 polite live region이다. 복잡한 상세 전체를 매번 음성으로 강제 낭독하지 않는다. 상세는 일반 탐색으로 읽는다.
- SVG 관계선은 장식으로 숨기고 동등한 텍스트 관계를 제공한다. 기능 아이콘은 하나의 선형 SVG 스타일, 명시적인 크기를 사용한다.
- 모바일 주요 명령과 메뉴는 최소 44px 높이다. ERD 노드는 전체 버튼 면적을 사용한다.
- 시스템의 reduced-motion 설정에서는 전환과 부드러운 스크롤을 생략한다. 브라우저 확대를 막지 않는다.
- OS 고대비 모드, 200% 확대, 실제 스크린 리더 사용성은 통합 단계에서 확인해야 한다. 화면의 작은 기술 메타데이터는 사용자 글꼴 설정에 맞춰 조정할 수 있다.

## 제공 상태와 남은 확인 사항

이 프로젝트 안에 `index.html`과 `design-notes.md`를 작성했다. 외부 저장소는 수정하지 않았다. 브라우저 미리보기, 스크린샷, 자동 테스트, 구문 검사, 실기기·보조기기 검증은 이번 작업에서 실행하지 않았다. 따라서 검증 통과를 주장하지 않는다.

기존 앱에 적용하기 전에 실제 스키마, 사용자 역할별 capability, 앱의 폰트와 테마 매핑을 확인해야 한다. 이 자료는 UI 참고용이며 운영 DB 마이그레이션, 실행 가능한 SQL 스크립트, 새 React 애플리케이션을 포함하지 않는다.
